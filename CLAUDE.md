# Questland Adventures — workspace guide

Pitch-ready mobile PWA for the Questland adventure park. App code lives in `questland/`.

## Stack
No CSS framework — DS tokens mirrored to `questland/src/theme/ds/*.css` (dark-first stone + gold-as-metal, from `design-system/`); `theme/tokens.css` is a BRIDGE keeping old var names (--parchment/--ink/--gold/--forest/--arcane/--ember + -soft) pointed at DS values. Local-first service layer (`questland/src/services/`, localStorage-backed) mirrors Firestore collections so Firebase can swap in later; components never touch localStorage directly. All lore/content is data in `questland/src/content/*.ts` — placeholder lore until user material lands in `content-intake/`.

## Handing work to the user (house rules)
- **`firestore.rules`: always print the ENTIRE ruleset as one copy-pasteable code block in chat.** Not a diff, not a file attachment, not "the changed blocks" — the Firebase console REPLACES the whole ruleset, so a partial paste silently drops every rule it omits. Summarize the delta in prose underneath, and say plainly whether the REST rules matrix has been run against the new blocks yet. File lives at repo root: `qa-mobile/firestore.rules`, NOT inside `questland/`.
- **`git fetch origin main` and merge BEFORE printing the ruleset.** Printing the whole file is not enough if the file is behind: a rules block that landed on main while your branch was out is missing from your copy, and pasting yours drops it through the closed `match /{document=**}` catch-all — silently, with no error, just a feature that stops working. Happened for real 2026-07-29 (PR #17's `announcements` block, caught by the user asking, not by me).
- **404 is an ALLOW when reading the REST matrix.** Firestore answers 403 when a rule refuses a read and 404 when the rule passes but the document is absent; a 5xx is not a verdict at all and the case must be retried. A harness that treats "not 200" as denied will report false failures on exactly the blocks you most want to trust.
- **UI work gets screenshots before moving on.** Capture the flow at 375x812 (guest) / ~1440 (console), send them, and WAIT for approval before starting the next task. Send them even when the data behind them is seeded/local-only rather than live — just label which parts are proven and which are only rendered. Harness: `scratchpad/shots.mjs` pattern — global playwright (`/opt/node22/lib/node_modules/playwright`), chromium at `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`, seed `ql:users`/`ql:session`/`ql:bookings:${uid}` via `addInitScript` + `sessionStorage['ql:gate-seen']` to skip the 5s gate intro, `waitUntil:'domcontentloaded'` (vite's HMR socket means networkidle never fires), and `dispatchEvent('click')` for map pins (they overlap at 375px).

## Gotchas & failure contracts (always loaded — the code will teach you the wrong thing without these)

**Layout / CSS**
- **TRANSFORM GOTCHA** (map went blank, PR #5 / b744c1b): a transformed element is the CONTAINING BLOCK for `position: fixed` descendants, and `fill: both` keeps it applied forever. `qa-ui-rise` therefore rises via **`top: 10px → 0`**, never `translateY`. **Never put transform/filter/perspective/will-change on the Outlet wrapper** — screens use `position: fixed` (MapScreen twice).
- **STACKING GOTCHA**: an animated `opacity` with `fill:both` makes a wrapper a permanent stacking context, so TopBar/BottomNav's `z-index:50` resolves INSIDE it and page content paints over the fixed bars. Both bar wrappers carry `position:relative; zIndex:50` (relative is safe — it does NOT re-parent fixed children). Final chain: video 0 < scrim 1 < Outlet 10 < bars 50 < shield 70 < toast 90.
- **SIZING GOTCHA** (console chart pinned left): a child's effects run before its parent's, so a one-shot mount measurement sized `MapCanvas` for a phone before `ConsoleScreen` lifted the 480px `#root` clamp. Measure with a **ResizeObserver on the viewport element**, never once on mount. Test harnesses that call `setViewportSize` after load hide this.
- **Gate intro timing**: CSS custom props are set in a **`useLayoutEffect`**, and the `var(x, fallback)` fallbacks must EQUAL the intro values — a post-paint `useEffect` or `0s` fallbacks flash the whole UI in at t=0. Never unmount `GateIntro`; it stays as the fixed backdrop. Do NOT re-encode `video-gate-opening.mp4` — runtime sets `playbackRate`.
- **Dialog bodies are capped at `52dvh` and scroll** — an uncapped long post grows the box until its own close button slides under the TopBar (TopBar z50 outranks a Dialog nested at z10).

**Firestore / rules / auth**
- **404 is an ALLOW when reading the REST matrix** (403 = refused, 5xx = no verdict, retry). A harness treating "not 200" as denied reports false failures.
- **Rules-query gotcha**: where a rule gates reads on the doc's own fields (`sos`, `legs`), a `where(...)` QUERY is refused 403 — the filter does not prove every match qualifies — while a delete addressed at ONE doc passes. Delete demo docs BY ID off the local mirrors, not by query.
- **Listener auth-race**: **Firestore never retries a listener it refused**, so signing in afterwards cannot revive it. All sync goes through `cloudSync.subscribeWhenAuthed(attach)`, which attaches only once `onAuthStateChanged` reports a REAL (non-anonymous) user.
- **No anonymous auth anywhere** — `signInAnonymously` is gone and the provider is disabled in the console. Every owner predicate in the rules requires `isRealUser()`.
- **A rules refusal arrives on a PERFECTLY VALID signed-in token** — `permission-denied` is a verdict on the request, not on the session, so `hasRealAuth()` is still TRUE. Never gate on it to predict or pre-empt a refusal: a Guide dropped from `staff/{uid}` passes every auth check and is refused every write. Cost a whole fix round in Aug 2026.
- **`catch { ...'unavailable' }` around a Firestore write conflates "no answer" with "refused".** Local-first fallback is right for the first and a silent lie for the second. Where a human is waiting on a verdict, classify the error `code` — and see `docs/plan-booth-refusal.md` for the paths still unfixed.
- **The committed `apiKey` in `services/firebaseConfig.ts` is public BY DESIGN** (security is via rules only). Do NOT flag it as a leak.
- **A guest missing from the console roster means that phone is on a local-only fallback account, not a sync bug** — its id is not a uid, so every owner-scoped query and `pushGuestProfile` is refused.
- **`tableAt` vs `updatedAt`**: a tap bumps `updatedAt` and NEVER `tableAt`, or every tap in the park marks all 21 stations stale. `tableVersion()` is derived as `max(tableAt)` — no hot counter doc.
- **⚠ The `demo-` id exception in the rules is demo-grade** and must be dropped for production.
- **`firestore.rules` lives at repo root, not inside `questland/`** — and see the house rules above for how it must be handed over.

**Domain rules that the code alone reads wrong**
- **A Quest Experience is spent at the chief's house only** (`checkIn(uid, QUEST_START.id)`); gate arrival and the episode's 7 stations are free. `redeem` is idempotent per (uid, orgId, episodeId).
- **The quest allowance belongs to the PASSAGE, not to each head** (`pass.quests`). Headcount is only how many it walks in (`PassUse.covers`). A passage booked for 5 still grants its own quota, not 5×.
- **Use `presenceService.questTaken(uid, orgId)`, never `activeQuest(uid)?.orgId === org.id`** — presence outlives the quest by its whole window, and a Hero Pass has all three questlines open at once, so the comparison locks two of them out.
- **18 of 21 stations are shared** (`orgId: null`; only the 3 base stations are owned), so a check-in must pass the questline's `orgId` explicitly or it credits the wrong order.
- **`updateAnnouncement` takes `null` to CLEAR `image`/`expiresAt`; `undefined` leaves them alone.** Without that a removed hero quietly stands.
- **A leg is written once** — the rules refuse `update` on `legs` entirely. Runs are DERIVED (`questRuns()`), never stored.

**Chat / push (the SOS thread lane)**
- **`catch { swallow }` is the right push everywhere EXCEPT a chat.** A message carries a LOCAL-ONLY `delivery` (`pending`/`sent`/`failed`); only the server clears it, and `pushSosMessage` is the one awaited write in `cloudSync`. Offline it stays `pending` forever ON PURPOSE — the SDK has it queued and nobody has received it. Never write `delivery` to Firestore.
- **Thread listeners differ by side, on purpose. CONSOLE = per screen** (a Warden may have dozens of calls; only the open one is worth watching). **GUEST = app-wide**, held by `startGuestSync` over their own non-resolved calls (≤`GUEST_THREAD_CAP`), so a reply lands wherever they are and a push-woken tap opens a thread that is already current. Do not "unify" these — a `collectionGroup('messages')` listener, or the console adopting the guest's pattern, is the one way to make this feature expensive (every warden's screen × every message in the park, forever). The board reads `lastMessage*` stamps on the parent `sos` doc instead. `ChatThread` takes `selfSubscribe` (guest passes false).
- **Two tabs on one browser is NOT a fair test of live sync.** The guest tab gets backgrounded and throttled while you type in the console tab, and `persistentMultipleTabManager` has them sharing a leader-elected connection — so replies land when the tab is foregrounded again and it looks like a broken listener. Test cross-device. Cost a full investigation on 2026-08-01.
- **`from` is checked against the caller in the rules**, not trusted from the payload — a guest posting `from:'warden'` would produce an official-looking answer in park livery from nobody. Messages are write-once (update/delete refused, like `legs`).
- **`pushTokens.staff` is a CLAIM, not a credential** — the collection is owner-writable. The Cloud Function re-checks every claimed uid against `staff/{uid}` before delivering. Do not "tighten" the rule believing the check lives there; `rules-tests/` asserts the split on purpose.
- **TWO service workers, two scopes.** The push worker registers at `${BASE}fcm/` — a second registration at the ROOT scope REPLACES workbox's and takes offline support with it. It carries NO Firebase SDK (importScripts from a CDN is a live network dependency inside the delivery path) and is kept out of the precache (`globIgnores`), because a SW served cache-first is one you cannot ship a fix to.
- **Sends are DATA-ONLY.** A `notification` payload renders in the background AND fires the foreground handler = two banners per message. Payload keys (`title/body/path/tag/sosId`) are a contract between `functions/src/index.ts` and `public/firebase-messaging-sw.js` — change one, change both.
- **`FCM_VAPID_KEY` must stay OUT of `FIREBASE_CONFIG`** — `isConfigured()` scans that object for `PASTE_ME` and would take the entire cloud offline. See `docs/push-setup.md`.
- **Re-mint the token on every app start** (`pushState()==='on' → enablePush`). The v9+ SDK dropped `onTokenRefresh`, so nothing else notices a rotated token and push dies silently.
- **`sos/{id}.userId` is IMMUTABLE on update, and that clause is load-bearing.** `ownsExisting()` reads the doc BEFORE the write, so without it the owner may hand their call to any uid — and the messages ACL (`call()`) and the push recipient both derive from that field. Caught by review, not by the suite, which had never written to a parent doc.
- **When a rule derives from another document's field, TEST WRITES TO THAT FIELD.** A subcollection suite that never touches its parent asserts the easy half.
- **The board's unread signal comes from the parent's `lastMessage*` stamps (`hasUnread`), never from `unreadCount`.** The message mirror is filled only by the on-screen thread listener, so a count taken on the board is structurally zero for every thread not already open — and opening one is the same gesture that marks it read. A boolean is the honest shape; an exact count needs messages the board deliberately does not fetch.
- **Read marks are keyed per `(sosId, viewer)` and advance ONLY on the other side's lines.** One key per thread let a Warden mark the guest's phone caught up (one origin, one localStorage), and taking the max across both sides let the console's clock carry the mark past a slow phone's message, which then landed already-read.
- **`fileToken` merges and only ever SETS `staff`, never clears it.** Guest app and console are two documents on one origin, so they mint the SAME FCM token and share one row — a plain `setDoc` from the guest side demoted the desk to `staff:false` and the back office went silent, with the console's UI showing nothing wrong.
- **Wait on the registration you just created, not `navigator.serviceWorker.ready`** — `ready` resolves the ROOT (workbox) registration and tells you nothing about the `fcm/` one; the SDK skips its own activation wait when handed an explicit registration, so `subscribe()` throws on a still-installing worker.
- **Enter-to-send is gated on `(pointer: fine)`.** The touch keyboard's return key fires a real Enter in a textarea on BOTH Android and iOS — cancelling it leaves a guest unable to break a line at all.
- **Rules suite: `cd rules-tests && npm install && npm test`** (emulator, needs Java; 44 cases). Reaches the staff cases the REST matrix structurally cannot, because `staff/{uid}` is unwritable by every client.

**Questland Radio ingest**
- **`@ffmpeg-installer/ffmpeg`, never `ffmpeg-static`.** ffmpeg-static fetches its binary in a postinstall script, so a build host that cannot reach GitHub at install time produces a package that reports success and then throws ENOENT on spawn at RUNTIME. @ffmpeg-installer ships the binary inside per-platform packages resolved as optional deps. `ffprobe-static` is fine — it carries its binaries in the tarball and has no install script.
- **NEVER `import { logger } from 'firebase-functions'`** (nor anything from `firebase-functions/v2`). The root barrel eagerly loads every provider including Realtime Database, which pulls `firebase-admin/database` -> `@firebase/database-compat` -> `@firebase/app` — an OPTIONAL peer npm is right not to install — and `firebase deploy` dies in codebase ANALYSIS with MODULE_NOT_FOUND before it examines a single function. Use `firebase-functions/logger` and per-provider paths. tsc is happy either way, so only loading the built bundle catches it: `functions/test/loads.test.mjs` is that guard.
- **The catalogue is LIVE in Firestore `radioTracks`; `soundtrack.ts` is only the FALLBACK** and is consulted solely when the live one is empty (un-seeded, refused, or first run offline). `setCatalogue` IGNORES an empty array on purpose — a refused listener and an unseeded collection both arrive looking like "no songs", and blanking a playing radio on either is worse than keeping the shelf in hand.
- **The ingest loop guard is a bill, not a bug.** `onRadioDrop` triggers on the bucket it also writes to; `routeDrop()` refuses anything outside `inbox/` and anything already in `inbox/_done/` before a byte is read. It lives in `radioEncode.ts` (Firebase-free) so `npm run radio:test` can prove it without a deploy. Never inline it back into the handler.
- **Folder is the playlist, filename is the title — the title is NEVER re-derived from the slug.** That round trip is what produced "Aldric S Way" in the first bulk encode.
- **A failed encode LEAVES the source in the inbox.** It is the only copy; a song swept into `_done/` after a failure is a song nobody knows is missing.
- **Encoder settings are duplicated in two places on purpose** (`scripts/encode-songs.mjs` and `functions/src/radioEncode.ts`) and must stay identical, or a new song sits at a different loudness to the 43 and jumps out on shuffle.
- **`getBlob()` is an XHR, so the bucket needs CORS** (`storage-cors.json`, applied with gcloud — neither the Firebase CLI nor the console can set it). With none, EVERY song fails to play and the SDK says `storage/unknown`, which reads as "check your connection". Cost an evening on 2026-08-19.

**Build / tooling**
- **PNG station masters are gitignored** — run `npm run stations` to regenerate the tracked webp. `park-map.png` (11 MB) is likewise optimized to webp before bundling; `vite.config.ts` `globIgnores` keeps the masters out of the 4 MB precache ceiling.
- **VitePWA injects the guest manifest into EVERY html entry**, after every `transformIndexHtml` handler AND after `generateBundle` — the duplicate on `console.html` can only be stripped in `closeBundle`.
- **The console mounts standalone** (`console-main.tsx`, no Router) and must supply its own `ToastProvider` — `SendWord` calls `useToast()`, which THROWS without one. Signed OUT the gate returns first and hides the bug; **test the SIGNED-IN console.**
- **The Firestore SDK round-trip is NOT verifiable in this sandbox** (headless Chromium gets `ERR_CONNECTION_RESET` through the agent proxy; node's fetch reaches googleapis, which is how the REST rules suites run). Cross-device behaviour needs a check on real hardware — say so rather than claiming it passed.

**Firmware / the wire**
- **`ql_line_open` publishes TYPE/DST/SRC/SEQ BEFORE the MAC check** (range-checked, zeroed on entry) so the hub's MAC-failure trace can name a mis-provisioned board. On any non-OK return those are **CLAIMED and UNAUTHENTICATED — log strings only.** Never route, credit, count or reply off them. Anyone can put any SRC on a line.
- **The `STATIONS` array's ORDER is the LoRa address.** `gen-clip-map.mjs` emits clip runs by array position while card manifests derive the address from the id; reordering `stations.ts` sends every plinth somebody else's speech, and the length check, 210-slot cross-assertion, canon fingerprint and `--check` all stay green. Guarded now — do not "fix" the guard.
- **`hubSerial` keeps the granted port across closes** — `requestPort()` needs a user gesture and the reconnect ladder is a timer, so clearing `this.port` means a human must re-pick the device on every reconnect.
- **The `.ino` files cannot be compiled here** (no `Arduino.h`/`LoRa.h`/`MFRC522.h`/`DFRobotDFPlayerMini.h`). Edited constructs can be checked against the real `config.h` + the `ql_crypto.h` stubs; that is not a board. Say so.
- **`npm run fw:kat` must be GREEN on a clean tree.** A drift guard that is red on day one cannot be gated on, so it gets ignored and then deleted. Fix a real disagreement at its source; never restore a known-bad number.
